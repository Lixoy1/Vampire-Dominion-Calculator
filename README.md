# Vampire Dominion — Blood Moon Edition

Независимый локальный калькулятор для игры «Наследие Вампиров», проект ОПТИМИСТ.

## Архитектура

- **Без бэкенда и Oracle API.** Сайт — статическое приложение: расчёты выполняются в браузере на устройстве игрока.
- `scripts/engine.js` — расчётное ядро: формулы, таблицы стоимости, прирост Господства и базовые алгоритмы распределения.
- `scripts/local-planner.js` — локальное планирование ресурсов, проверка плана, призыв и полный расчётный снимок; использует `engine.js` и `data.js` напрямую.
- `scripts/data.js` — встроенная база: 68 смотрителей, 45 партнёров, 237 предметов, 8 ступеней прорыва, 180 уровней Конклава, 210 уровней Сада и 155 строк кривых Веяний.
- Профили хранятся в `localStorage`. Экспорт и импорт JSON выполняются на устройстве и подходят для переноса на другой телефон.
- Внешние игровые API не используются; значения аккаунта игрок вводит вручную.

## Запуск

Можно разместить папку на GitHub Pages или Render Static Site. Для локального просмотра запусти простой сервер статических файлов:

```bash
python3 -m http.server 8080
```

Затем открой `http://localhost:8080`. Этот сервер только раздаёт HTML, CSS и JS; никакие вычисления на нём не выполняются. Не открывай `index.html` через `file://`, так как браузер может блокировать ES-модули.

## Quick Calculation: формат API

- `scripts/quick-settings.js` реализует нормализацию параметров оригинального Quick endpoint: цель, 10 переключателей расходов, исключения по смотрителям/партнёрам и исключения атрибутов Конклава.
- `quickResponseToPlan` преобразует серверные `conclave`, `levels`, `bonds`, `talents`, `presences`, `auras` и `skins` в поддерживаемые поля локального плана.
- UI сохраняет настройки, экспортирует JSON тела запроса и позволяет импортировать небольшой JSON-ответ или HAR с успешным `/calculations/quick`. Импорт создаёт предварительный план и требует явного подтверждения; ресурсы не списываются.
- Оригинальный Quick optimizer выполняется на сервере. Его алгоритм не находится в загруженных клиентских JS-модулях и не заменяется фиктивным локальным алгоритмом. Уровни Вдохновений и предметы exp_items помечаются как неподдерживаемые локальной моделью.

## Эталон HAR и оформление Crimson

- Все четыре captures сведены в обезличенный аудит: 3 487 сетевых записей, 1 251 API-вызов, 78 успешных отчётов Господства и 17 успешных ответов Quick. Подробности потоков и ограничений — в [docs/HAR_COVERAGE.md](docs/HAR_COVERAGE.md).
- HAR задаёт структуру экранов, полей, вкладок и сценарии действий; визуальная система остаётся нашей — Crimson Obsidian / Blood Moon.
- Карточки Смотрителя используют 6 отдельных секций, Партнёра — 4; настройки локального профиля не имитируют серверное подключение или сообщения игрового бота.

## Проверка расчётных наблюдений

- `scripts/observed-costs.js` хранит 32 разреженные цены `next_cost`, непосредственно подтверждённые успешными ответами API из HAR.
- `scripts/workbook-blood-costs.js` содержит историческую таблицу из 500 переходов крови из пользовательской книги `Kalkulyator_gospodstva_Nadya_495.xlsx` (v1.4, 09.08.2026). Она используется как более обоснованная оценка вместо прежней экспоненциальной формулы, но **не считается точным актуальным серверным справочником**.
- Приоритет расчёта: точное значение HAR → строка исторического Excel → старая резервная кривая, если строки нет. Для каждого смотрителя интерфейс показывает, сколько шагов пришло из каждого источника.
- Сверка 32 HAR-точек с Excel выявила близкие значения на многих уровнях, но также существенные конфликты на уровнях 350 и 400; в этих случаях всегда выигрывает HAR.
- Для Кровных уз сохранены отдельные наблюдённые цены по типу ветви (`default`, `one`, `two`, `all`) и виду шага (плоский / процентный).
- Между наблюдёнными точками HAR ничего не интерполируется. Строки Excel остаются историческими оценками, помеченными в предупреждениях.
- Сырые HAR и пользовательские данные аккаунта в репозиторий не добавляются.
